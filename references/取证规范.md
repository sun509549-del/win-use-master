# Windows GUI 取证规范

**什么时候读这份**：截图要进入项目、需要证明某一步确实生效、要组织一批可重跑的 GUI 实测，或要裁剪、压缩、归档与对外发布证据。

这份规范的目标不是“多截几张图”，而是让每张图回答四个问题：**截的是谁、何时截、怎么截、它能证明什么。**

## 一、原图、加工件、发布件分离

推荐目录：

```text
evidence/
  raw/                   # 原始 PNG、命令输出、窗口收据；只增不改
  derived/               # 裁剪、标注、拼图、压缩件
  published/             # 用户确认可发布的最终版本
  recipes/               # 可重放的 PowerShell/CDP 动作脚本
  ledger.md              # 台账：步骤、状态、路径、哈希、例外
  _archive/              # 弃用件；移动进来，不删除
```

若用户项目已有结构，以用户结构为准；不要为了套模板搬动现有文件。截图直接落项目证据目录，不落桌面或系统临时目录后再遗忘。

硬规则：

- 原始 PNG 永不覆盖；重截使用新序号或新时间戳。
- 裁剪、打码、标注只写 `derived/`，能从原图重放。
- 清理只移入 `_archive/`；未经用户明确要求不永久删除。
- 上传、发消息、公开链接不是取证步骤，不自动执行。

## 二、命名

文件名要可排序、可配对、避免 Windows 非法字符。推荐：

```text
<批次>-<步骤序号>-<动作>-<before|after|result>-<YYYYMMDD-HHmmss>.png
```

例如：

```text
login-03-type-account-before-20260907-142501.png
login-03-type-account-after-20260907-142504.png
```

不要在文件名中使用 `<>:"/\|?*`，也不要只用窗口标题：标题会变化、重复，还可能包含隐私。

多对象/多模型同题跑批时，时刻名必须跨对象逐字一致：

```text
<题>-<对象>-01初始状态.png
<题>-<对象>-02输入完成.png
<题>-<对象>-03最终结果.png
```

先确定“题 / 对象 / 时刻名”三元组，再开始采集，避免后续靠人工猜配对。

## 三、每张原始证据的收据

原图旁至少保留这些信息，可写进同名 `.json`、`.txt` 或批次台账：

| 字段 | 内容 |
|---|---|
| `captured_at` | 带时区的 ISO 8601 时间 |
| `method` | `PrintWindow`、`PrintWindow sibling-renderer recovery`、`PrintWindow`（前台稳定帧）或 CDP `Page.captureScreenshot` 等 |
| `command` | 去除密钥、token 与敏感文本后的可重放命令 |
| `hwnd` / `pid` | 当时值，仅用于本次追踪，不当永久身份 |
| `owner` / `title` / `class` | 当时的进程、标题、窗口类 |
| `rect` / `dpi` / `state` | 窗口位置尺寸、缩放、最小化/cloaked/foreground 状态 |
| `source_size` | 图像像素尺寸与文件大小 |
| `sha256` | 原文件哈希 |
| `effect` | `confirmed` / `partial` / `suspected_noop` / `unverifiable` |
| `proves` | 这张图能证明的最窄命题 |
| `caveat` | 黑帧风险、裁剪、遮挡、旧帧、敏感区等 |

PowerShell 计算哈希：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath .\evidence\raw\example.png
```

HWND 会在窗口关闭后失效，也可能被系统复用；长期身份用 exe 路径、包标识、版本和窗口类组合描述。

## 四、before / action / after

可逆 GUI 动作至少保留：

1. `before`：动作前窗口状态；
2. 动作收据：所用层、目标元素/ref 或归一化坐标、安全闸结果；
3. `after`：动作后状态；
4. 语义验证：读回属性、按钮状态或业务副作用。

`win.ps1` 的修改型命令会把前三项的机器可读摘要写入 after 图的 `.receipt.json`：`action` 记录层、动作种类、脱敏目标、文本长度与焦点时长，`verification` 记录 before/after SHA-256、像素差分和 effect。UIA `uiaset` 还记录 `semanticReadback`。CDP 的 `click/text/mouse/insert/press/act` 写独立 `action-receipt-v1`：target URL 去 query/hash，selector 只保留短 ref 或 CSS 的 SHA-256/长度，输入只记长度，页面内容只形成交互树摘要哈希和差分计数。输入正文不进入收据；before 临时图删除后仍保留其哈希。业务副作用需要调用方独立回读，不能由像素或 DOM 差分代填。

像素差分只能证明“画面变化”，不能证明“操作正确”。下列变化都可能是假阳性：

- 文本光标闪烁；
- hover/focus 边框；
- 时间、进度条、视频、动画；
- 通知弹出；
- `PrintWindow` 从旧帧刷新到新帧，但业务动作没发生。

反过来，画面无变化也不一定表示业务无变化，例如后台文件已写入。最终判据优先级：业务副作用 > 应用状态指示器 > 控件读回 > 可见文字 > 命令返回。

对于追加型输入、发送、提交、删除等非幂等动作，`unverifiable` 或超时后先检查最终状态，**不能直接重放**。

## 五、截图方法要写进证据结论

不同捕获路径证明范围不同：

- `PrintWindow`：可能在被遮挡时获得窗口图，但也可能由 app 返回黑帧、旧帧或缺少硬件加速层。它证明“目标窗口在该调用下返回了这张图”，不自动证明用户屏幕当时看到同一画面。
- `PrintWindow sibling recovery`：证明同位置且有进程血缘的另一个窗口返回了图；收据必须写 `recoveredFrom`，不能把渲染 sibling 冒充原请求 HWND。
- `shotfg`：仍是 `PrintWindow`，只是接近空图时短暂借前台并等待连续稳定非空帧；不能写成“屏幕可见区域截图”。
- CDP：证明该渲染 target 的页面内容；通常不含原生标题栏、系统对话框和另一个进程的 UI。
- `see` 缩略图：用于 agent 决策；若经过降采样、拼接或叠加元素表，不作为唯一原始物证。

不能把一种路径的限制藏掉。例如用 CDP 截到网页内容后，不应宣称“完整桌面窗口截图”；用 `PrintWindow` 截到旧帧后，不应把时间戳写成业务状态发生时间。

## 六、尺寸、格式与加工

- 原始证据优先保留无损 PNG 与原始像素尺寸。
- 面向文档的发布图可转 JPG/WebP、限制长边和体积，但必须从原图生成并保留映射。
- 裁剪不得去掉理解结论所需的窗口身份、状态指示器或异常提示；如必须裁剪，在台账中记录裁剪框。
- 标注使用单独图层或可重放脚本；不要把箭头直接烧进唯一原图。
- 截固定尺寸产物时，先把视口/窗口尺寸对齐设计尺寸。窗口缩放造成的裁切不能归因给被测 app。

Windows 混合 DPI 下，截图像素与窗口矩形可能受 DPI 感知方式影响。DPI-unaware app 的 `PrintWindow` PNG 可能采用逻辑像素，而窗口矩形是 DWM 物理像素；收据应同时记录两者尺寸和 `imageToWindowScale`。窗口换显示器后重新基准，不沿用上一轮坐标或裁剪框。

## 七、隐私、凭据与对外发布

截图前读项目自己的禁词/隐私清单；通用检查包括：

- 用户名、邮箱、手机号、头像、聊天与联系人；
- 本机路径、网络共享路径、项目名、侧栏其他任务；
- API key、token、二维码、Cookie、会话 ID；
- 未发布产品/模型名、内部代号、客户资料；
- 通知中心、任务栏预览、其他窗口意外露出。

命令收据和终端差分都要脱敏。不要把 token 放在命令行再原样写台账；必要时只记录 `<redacted>`、token 来源与哈希指纹。CDP 输入框、文本域和可编辑区域的旧值/新值只报告字符数；普通非编辑控件标签才可进入人读差分。

加工件与原图分离不等于原图可以公开。`raw/` 应留在用户指定的受控目录；对外发布前由用户确认。识别不确定时宁可停在本地，不自动上传图床。

## 八、可重放配方

动作配方应记录“怎么重新发现目标”，而不是只记易腐的 HWND 和绝对坐标。推荐包含：

```text
目标解析：exe/包标识/进程名/窗口标题规则
前置条件：版本、窗口尺寸、显示器 DPI、登录态、允许的控制层
探测：probe 输出摘要与 L0/L1 判据
动作：结构选择器或 UIA 属性；坐标只用归一化 + 锚点
等待：可观察条件与超时
安全：需要人在场/会借前台/不可执行的最后一步
验证：读回与最终副作用
产物：原图、收据、日志、哈希
```

CDP `ref=eN`、UIA 短 ref、HWND 都是会话内引用，不能跨重放持久化。配方中存“按文本/role/AutomationId/父子关系重新寻找”，并在零命中或多命中时停止。

## 九、跑批公平性

多 app、多模型或多版本对比时：

- 输入题面逐字一致，并从 app 最终状态或 transcript 回读，不只相信发送端字符串；
- 每轮起点一致，共享目录中的上轮产物移入可追溯归档，不删除；
- 使用同一组窗口尺寸、DPI、动作与定点截图时刻；
- 每一跑写“有效 / 作废”及原因；
- 采集期保留耗时、重试、安全拒绝与工具调用，发布期再筛；
- 不默认输出排名或公开横向比较，除非用户明确要求。

如果某轮因 UAC、用户抢回焦点、通知遮挡、锁屏、窗口换显示器或安全闸拒绝而偏离配方，应标作废或单独注明，不能悄悄补点后混入同组。

## 十、锁屏与无人值守

锁屏期间 L0 任务可能继续，但 L2 输入和可信像素证据不能继续。正确做法只有两类：

- 把 GUI 步骤标成“需活动交互桌面/人在场”，解锁后补采；
- 将可验证部分改为 CLI、应用 API、CDP 状态或文件副作用，并明确这不是屏幕证据。

不得复用锁屏前截图冒充锁屏后结果，也不得用猜测的旧 HWND 继续坐标写。

## 十一、收工检查

- 原图未被覆盖，SHA-256 已记录；
- 每个 after 都能追到 before、动作与验证；
- `PrintWindow`/CDP/前台截图的能力边界已注明；
- 黑图、旧帧、空图、通知、HUD 与遮挡已抽查；
- 坐标含锚点、窗口尺寸、DPI 和版本，不只有数字；
- 日志和命令已脱敏；
- 弃用件进 `_archive/`，没有永久删除；
- 发布动作仍由用户决定；
- 本轮可复用且有证据的教训已回流到代码或 `app档案.md`。
