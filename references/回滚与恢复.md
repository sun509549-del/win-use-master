# 回滚与恢复

回滚目标是切换到一个已验证的旧发布，而不是覆盖当前工作区。当前 manifest 的 `previousStable.version/tag` 都是 `null`，表示仓库尚无正式上一稳定版本；在首个发布完成前，不能声称存在一键稳定回滚。

## 发布前验证回滚能力

1. 选择已经发布、校验和和远程 CI 都已确认的精确 tag；分支名、浮动 `main` 和本地 commit 描述不能作为稳定目标。
2. 把旧 tag clone 到一个新的明确目录，不覆盖当前安装：

```powershell
$ROLLBACK_DIR = 'C:\path\to\win-use-master-rollback'
git clone --branch <verified-tag> --depth 1 https://github.com/sun509549-del/win-use-master $ROLLBACK_DIR
git -C $ROLLBACK_DIR rev-parse HEAD
Get-Content -LiteralPath (Join-Path $ROLLBACK_DIR 'VERSION')
pwsh -NoProfile -File (Join-Path $ROLLBACK_DIR 'scripts\build.ps1')
pwsh -NoProfile -File (Join-Path $ROLLBACK_DIR 'scripts\win.ps1') doctor --summary
pwsh -NoProfile -File (Join-Path $ROLLBACK_DIR 'tests\run-tests.ps1') -Tier Contract
```

3. 对照 Release Notes 中的 published commit、tag、版本和 SHA-256。任一不一致都停止，不切换 agent 的 Skill 路径。
4. 在隔离桌面完成旧版本所需的 Desktop/Coordinate/真实应用抽查，再由用户切换到新目录。

不要对含用户修改的安装目录执行 `git reset --hard`、强制 checkout 或覆盖复制。不要递归删除旧目录；先保留它作为可恢复副本，待用户确认新旧版本和本地证据去向后再处理精确目录。

## 本地状态兼容

- 能力缓存不是授权来源；版本变化会使记录失效。回滚后可用 `cache show --json --summary` 查看，再按用户决定精确清除。
- CDP session 绑定进程、启动时间、target 和期限，不能跨升级或回滚复用。关闭旧授权实例后重新建立会话。
- `HuWin.dll` 是源码派生物；每个 checkout 都从自己的 `HuWin.cs` 重建，不从新版本复制到旧版本。
- 用户 evidence 可能包含敏感内容，也可能使用新 schema。旧版本遇到未知 schema 必须停止或人工检查，不能按旧结构继续动作。
- `.last-update-check` 只是本地日期，不证明版本或安全状态。

## 发布后故障

1. 停止继续发布和自动升级，记录受影响版本、目标 commit、控制层、退出码和不含正文的复现摘要。
2. 若涉及凭据或敏感证据，先轮换/隔离并按 `SECURITY.md` 使用私密渠道；不要把日志、截图、UIA map 或 DOM 快照贴到公开 Issue。
3. 将有问题的版本标为已知故障，但不要移动或复用原 tag。
4. 引导用户安装 manifest 中登记的 previous stable；如果该字段为空，就明确没有已验证回滚目标，不能随意选择历史 commit。
5. 修复走新的 patch/prerelease 版本，重新完成全部发布门，不在原 tag 上替换内容。
