# 性能基线

> 首版日期：2026-09-15
>
> schema：`win-use-master/performance-report-v1`
>
> 定位：可重复的回归参考，不是跨机器 SLA，也不是放宽安全截止时间的理由。

## 1. 运行方式

标准档对重复进程、每个 UIA 规模和 CDP inspect 各采 5 个样本：

```powershell
& "$SKILL_DIR\scripts\win.ps1" benchmark --summary
& "$SKILL_DIR\scripts\win.ps1" benchmark --json --summary
```

开发期快速档将重复进程和 CDP 降为 2 个样本、每个 UIA 规模降为 1 个样本：

```powershell
& "$SKILL_DIR\scripts\win.ps1" benchmark --quick --json --summary
```

若当前环境不应启动临时无头 Edge，使用 `--no-cdp`。此模式不创建临时 profile，仍测 `windows` 与合成 UIA：

```powershell
& "$SKILL_DIR\scripts\win.ps1" benchmark --quick --no-cdp --json --summary
```

重复、未知参数在任何测量前退出 `2`。必需的 `windows`/UIA 失败，或已经启动的 CDP fixture 执行/清理失败时退出 `1`；Node/Edge 缺失只让可选 CDP 组为 `skipped`、总状态为 `partial`，不会把 UIA/Win32 核心误报为失败。命令只向 stdout 输出文本摘要或一个 JSON 文档，不自动保存报告。

## 2. 测量口径

| 组 | 实际测量 | 明确不代表 |
|---|---|---|
| Windows first | helper 已构建的前提下，第一个全新 `pwsh` 进程执行 `windows --json --summary` 的端到端耗时 | DLL 首次编译；进程内热调用 |
| Windows repeated | 后续全新 `pwsh` 进程的端到端耗时；OS 文件缓存可能已热 | 同一进程内缓存命中 |
| UIA 100/300/1000 | 实际生产 `Get-UiaReadablePage` 在确定性 provider double 上查询并返回前 50 项；每档先做一次不计时 warmup | 真实应用 provider、跨进程 worker 启动或桌面兼容性 |
| CDP inspect | 项目自启、所有权可识别的临时无头 Edge 上执行 `inspect auto body --json --summary` 的子进程端到端耗时 | 真实 CEF app、网络页面或写动作延迟 |

统计使用 nearest-rank 的 p50/p95，同时给出 min/max/mean。标准档每组只有 5 个重复样本，因此这里只适合作为粗粒度回归预警；要做稳定优化结论，应在同一机器、同一电源状态和相同 profile 下多轮复测。

UIA 报告中的 `timeoutBudgetMs=6000` 只是与现有生产预算比较，`budgetExceededCount/rate` 表示样本是否超过预算。合成 provider 不会被当作真实 worker 超时测试；真实隔离与终止语义继续由 `tests/uia-timeout.ps1` 验证。

## 4. 报告边界与副作用

benchmark 子进程设置“只允许预构建 helper”的内部条件；DLL 缺失、比源码旧、损坏或不可加载时直接失败并建议先运行 `build.ps1`，不会让 `win.ps1` 的日常自动编译回退污染计时或产生意外仓库写入。

`performance-report-v1` 只保留聚合统计，不保存原始样本、命令 stdout/stderr、窗口数量、标题、页面内容、target id、CSS selector、端口或路径。`sideEffects` 会明示：

- `windows` 摘要元数据读取次数，以及窗口标题报告数固定为 0；
- 桌面输入事件、真实应用启动、写命令基线和报告文件写入均为 0；
- CDP 是否启动一次临时无头浏览器，观察到多少该 profile 所有的 Edge 进程，结束后还剩多少；
- 临时 profile 目录创建与回收数量。

默认 CDP 路径会让 Edge 在项目专属临时 profile 中创建内部文件，因此它不是文件系统零写入模式；这些内容必须随已验证的精确目录回收。`--no-cdp` 才是本入口的零临时目录模式。无论哪种模式，都不连接、启动或控制用户的真实应用，也不产生键鼠输入。

## 5. 回归判断

首版建议把“同一机器、同一 profile、同一 fixture 的 p95 比最近可接受基线上升超过 20%”当作人工预警，而不是自动发布失败。出现预警时至少复跑三轮，并先排除：

- Windows 更新、杀毒扫描、电源模式和后台负载；
- helper 未预先构建，导致本来不应发生的编译；
- Node/Edge 大版本变化；
- 采样数或 quick/standard profile 不一致。

任何优化都不得通过以下方式换数字：延长 UIA/CDP 写入截止时间、取消 UIA worker 隔离、跳过 owner/session/target/前台/UIPI/用户在场/风险规则校验，或把 `unknown` 重试成可能重复的非幂等写入。

## 6. 尚未进入首版的项目

- PrintWindow 成功率、超时率和 sibling recovery：需要专用空闲交互桌面，不能在当前只读/无头轮次伪造。
- CDP `insert/press` p50/p95：它们是真实写命令，必须另建一次性授权、完全隔离且可撤回的 fixture；本轮 `writeCommandsBenchmarked=0`。
- 真实应用 UIA、截图和 CDP 性能：必须按应用版本、桌面状态和控制层单独记录，不能混入合成基线。

对应契约为 `tests/benchmark-contract.ps1`：它在 `--quick --no-cdp` 下验证统计、schema、隐私、仓库逐文件零修改、参数预拒绝和生产超时常量未被放宽。完整 CDP 路径应在发布前按需实跑，并核对临时目录已删除、专属 Edge 进程剩余为 0。
