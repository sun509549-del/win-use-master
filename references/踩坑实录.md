# Windows 踩坑实录（2026-09-08 起）

**什么时候读这份**：想知道某条闸、某个提示、某个测试断言为什么长成这样；或者准备把一条"经验"写进正文之前，先看它是不是已经被推翻过。

每条按“现象 → 归因 → 落点（改了代码还是只进了档案）→ 证据”写。所有条目都来自本机实测，日期就是标题里的日期；Mac 版的同名文件记的是 macOS 的坑，这里不重复，只在最后一节写“哪些 Mac 结论在 Windows 上不成立”。

## 一、判空与截图

### 1. 空白记事本被判成“截图失败”

- 现象：`see` 一个刚打开的记事本 11，PrintWindow 明明完整（标签、工具栏、状态栏都在），收据却写 `colorBuckets=1`，提示“接近纯色，改 shotfg / CDP”。
- 归因：判空只统计裁掉标题栏、工具栏、边框后的内容区，空白文档就是一张白纸。校准发现空记事本和黑壳窗口在内容区都是 1 桶、整帧都约 20 桶——像素上无法区分。
- 落点：不改阈值。收据加 `frameColorBuckets`；整帧也单色才说“可能拒绝渲染”；`see` 用当次 UIA 表做语义交叉——读到空的 Document/Edit 就写“与空文档一致，不是截图失败”；`shotfg` 在这种情况下不借前台。
- 证据：`tests/notepad-profile.ps1` 的 `blank-heuristic` 段。

### 2. 隐藏窗口被标成 `state=current`

- 现象：剪映编辑器进程起来后，`windows --all` 列出主窗、「版本更新」弹窗、CEF 窗，全部 `state=current`，但截图整帧 1 桶、UIA 空树、`screen` 拒绝。
- 归因：这些窗口 `visible=False`。原来的状态字段只区分 min / cloaked / current，没有 hidden。
- 落点：`state=hidden`；`shot` 直说“窗口不可见，空帧是预期”；`screen`、坐标写、`shotfg` 对隐藏窗口拒绝——激活它会 `ShowWindow`，等于替用户把托盘 app 弹出来。
- 证据：剪映档案第二次观察；`clickin --dry` 的 `desktop=BLOCK(hidden)`。

### 3. 刚还原的窗口第一帧直接失败

- 现象：把最小化的 QQ 主窗 `restore` 后立刻 `see`，PrintWindow 返回失败（不是空帧，是没图）；几秒后再 `shot` 就是 1734x1461、232 桶的完整图。
- 归因：Electron 首帧尚未提交。
- 落点：`Invoke-BackgroundShot` 首次直接失败且窗口未最小化时等 400 ms 重试一次，收据 method 标 `retry-after-400ms`。只重试一次，不循环。
- 证据：QQ 档案 L3。

### 4. `screen` 拍到的是别的窗口

- 现象：WPS/Excel 私有实例的窗口、`restore` 回来的 QQ 与微信，`screen --window` 采样 5/5 都被前台的 Cursor 盖住；剪映环境检测弹窗被 QQ 盖住。
- 归因：新窗口和不激活还原的窗口默认排在前台窗口后面；桌面合成拍的是用户此刻看见的像素。
- 落点：`screen` 一直只作交叉验证，收据带 occlusion；这条进了共性结论第 6 条。PrintWindow 才是被遮挡窗口的内容来源。

### 5. “最大的那个窗口”是阴影

- 现象：WPS 私有实例里最大的可见窗口是 `KLiteMainWindowShadowBorder`（891x560），对它截图 1 桶、UIA 空；真窗口是小一圈的 `XLMAIN`（867x536）。
- 落点：WPS 档案回归按 `class=XLMAIN` 选窗；`Resolve-HuWindow` 按面积选最大窗口的默认策略对这类 app 不可靠，档案里写清。

## 二、UIA

### 6. 文本区是 Document，不是 Edit

- 现象：记事本 11 的 `uia` 列不出文本区，`uiaset first` 找不到目标；`uiaread` 却能看到 Document「文本编辑器」。
- 归因：RichEdit/WinUI 编辑器把文本区暴露为 ControlType.Document（class `RichEditD2DPT`），带 ValuePattern；worker 的动作元素类型表里没有 Document。
- 落点：worker 纳入 Document；`first` 先 Edit、无 Edit 时兜底带 ValuePattern 的 Document；`uiaset` 对 Document 的像素验证点改到首行附近（原来取控件中心，落在空白处报 `suspected_noop`）。
- 证据：`tests/notepad-profile.ps1`。

### 7. Qt 的两种脸：微信空树、剪映挂死

- 现象：微信 4.1（Qt 5.15）`uia`/`uiaread` 1–2 秒返回 0 个元素；剪映 10.4（Qt 6.2）两个命令都超过 6 秒被隔离 worker 终止。
- 归因：Qt 的 UIA provider 实现随版本差异很大；不能按“Qt”预测。
- 落点：只进档案与共性结论第 3 条。剪映那次是隔离 worker 设计价值的直接证据——在 agent 进程里直接调 UIA 会卡死整个会话。

### 8. 上限 180 / 300 会先撞到

- 现象：Excel `uia` 正好 180 个（功能区按钮就够了），网格单元格到不了；QQ `uiaread` 正好 300 个，几乎全是会话文字。
- 落点：暂未改上限——放开会把隐私文本和噪声一起放进上下文。档案写“有 COM 就不需要网格”“QQ 的可读文本含隐私”。

### 9. Electron 的两种脸：QQ 可读、WorkBuddy 空树

- 现象：QQ NT 的 Chromium 树对 UIA 完整（47 个 Button、1 个 Edit、1 个 Document + 300 条文本）；WorkBuddy 主窗 UIA 只有 Pane/Window。
- 落点：共性结论第 3 条“不按框架猜”。WorkBuddy 走 CDP；QQ 没开 CDP 时 UIA 反而是可用层。

## 三、启动与窗口状态

### 10. `open` 不等于“显示已运行的窗口”

- 现象：`open QQ` 弹出第二个登录窗（QQ NT 允许多账号并行）；再启动剪映根启动器，转交给已运行实例后什么都不显示；Excel/WPS 的 COM 永远新起私有进程。
- 落点：`restore`/`minimize` 两个显式命令（`SW_SHOWNOACTIVATE`/`SW_SHOWMINNOACTIVE`，不主动取得前台，隐藏窗口拒绝，打印窗口状态和前台迁移）；档案与共性结论第 2 条。我误起的 QQ 第二实例用 `CloseMainWindow` 关掉，正常退出。

### 11. Excel 的 `Visible = True` 被忽略，`Hwnd` 还会换

- 现象：pwsh 7 里 `New-Object -ComObject Excel.Application` 后设 `Visible = $true`，读回仍是 False，XLMAIN 隐藏，UIA/截图全空；先怀疑 pwsh 7 的 COM 绑定，用 5.1 对照结果一样。
- 归因：这版 Excel 在没有工作簿窗口时忽略 Visible；`Workbooks.Add()` 之后 Visible 生效，并且 `Application.Hwnd` 换成新的 XLMAIN，启动时拿到的句柄留在隐藏态。
- 落点：`tests/excel-com-profile.ps1` 先 Add 再设 Visible，之后重新读 Hwnd；控制面详解 COM 节。

### 12. 记事本关闭不提示，内容留到下次

- 现象：第一次跑记事本回归在写入后中断，`CloseMainWindow` 直接关掉没有提示；下次启动恢复出带测试文本的标签，被自己的“拒绝写入恢复会话”闸拦住。
- 归因：记事本 11 默认保存会话，关闭已修改标签不弹保存框。
- 落点：测试的 finally 在写过而未还原时先清空再关；档案“会话持久化”一节。残留用定向清理（只在唯一标签内容恰好等于测试文本时清空）处理。

## 四、COM

### 13. WPS 把自己伪装成 Excel

- 现象：probe 在 WPS 目录下列出 `Excel.Application.12 → et.exe`、`Excel.Sheet.12 → wps.exe`；WPS 私有实例的 `Application.Name` 报 “Microsoft Excel”、窗口类名 `XLMAIN`。
- 归因：兼容性抢注，在 32 位注册表视图；64 位宿主拿到微软 Excel，32 位宿主可能拿到 WPS。
- 落点：两个 COM 档案回归都用 `Application.Hwnd → pid → exe 路径` 核对身份；要 WPS 用 `KET.Application`。任何按名字判断“是不是 Excel”的逻辑在装了 WPS 的机器上都不可信。

### 14. PowerShell 里用 COM 的三处暗坑

- `Range.Value2 = 3`（Int32）在 pwsh 7 报 “cannot cast Int32 to String”，写 `[double]` 就好。
- COM 对象不能从函数 `return`：`Workbooks` 这类集合会被 PowerShell 展开，空集合变成 `$null`；用 `Write-Output -NoEnumerate` 包一层，属性写入又会找不到属性。赋值后再登记引用。
- Range/Worksheet/Workbook 的 RCW 不释放就 `Quit()`，`/automation` 进程会一直活到 DCOM ping 超时（约 6 分钟）；全部 `FinalReleaseComObject` 后 30 秒内正常退出。第一次跑留下了一个无窗口的 EXCEL.EXE 和它派生的 0 线程子进程，就是这么来的。

## 五、CDP 与端口

### 15. 有本地端口 ≠ CDP

- WorkBuddy 默认启动有多个 127.0.0.1 端口，`/json/version` 全 404；QQ 有两个 HTTP 200、一个 HTTP 400；微信 14013–14023 无响应；剪映 7264 无响应；WPS 云服务 4709。全都不是 CDP。
- 落点：`open --cdp` 只认 `webSocketDebuggerUrl` 且 owner 属于目标进程树；probe 逐端口写“非 CDP（HTTP 200）”而不是只列端口。

### 16. `role=textbox` 编辑器把输入全文打进日志

- 现象：对 WorkBuddy 的 Slate 输入区 `insert` 后，终端差分打出 `text "今天帮你做些什么？…"→"win-use-master cdp probe"` 全文。
- 归因：脱敏靠 `kind` 后缀 `/editable` 判断，而 `role=textbox` 让 kind 变成 `div/textbox`。
- 落点：采集时按 `isContentEditable`/input/textarea/`role=textbox|searchbox` 打 `editable` 标记，差分只显示字符数；`tests/cdp-action-receipt.ps1` 加了 `role=textbox` fixture 守住。

### 17. 撤回要走真实键事件

- 现象：需要把刚 `insert` 进 Slate 的内容撤掉；`text`（直接改 textContent）对 Slate 不可信（Mac 档案已记）。
- 落点：`press SelectAll`（Ctrl+A，只选中当前编辑宿主）+ `press Backspace`；WorkBuddy 上发送键 `disabled` 状态随之来回，占位符重现。

## 六、PowerShell 与环境

### 18. `see --out` 在 `pwsh -File` 下崩

- 现象：`pwsh -File win.ps1 see 0x123 --out C:\x.png` 在脚本运行前失败：“parameter name 'out' is ambiguous: -OutVariable -OutBuffer”。进程内 `& win.ps1 ... --out` 正常。
- 归因：`-File` 宿主把能前缀匹配公共参数的 token 当参数名绑定；`--window`、`--region`、`--dry` 等不撞任何公共参数所以没事。
- 落点：`see <target> <path>` 位置参数；smoke 用真实子进程覆盖；文档里原本会失败的示例改掉。

### 19. Windows PowerShell 5.1 不能跑这个项目

- 现象：用 5.1 跑 `build.ps1`/带 UTF-8 中文的脚本解析失败；agent 的 Shell 包装器还会在 bash 和 5.1 之间切换。
- 落点：README/SKILL 明说必须 pwsh 7；实测时用无空格完整路径 `C:/…/pwsh.exe -File 脚本` 这种两边都能解析的调用形式。

### 20. probe 的安装根前缀匹配到了隔壁目录

- 现象：probe QQ 时把 `D:\ruanjian\qqyinyue\...\QQMusicSvr.exe` 的 COM 服务器算进 QQ。
- 归因：`IndexOf('D:\ruanjian\qq')` 是纯前缀匹配。
- 落点：目录级匹配（根路径加尾部反斜杠）。

### 21. 两个被负载放大的测试假设

- smoke 的“自身输入尾迹”断言原本在 UIA 读回循环之后采样，机器同时跑着四个 app 时读回用了 5.5 秒，`raw ≥ 3` 就假失败；采样点移到 `op` 刚结束。
- CI 的无头 Edge 就绪只等 12 秒，冷 runner 上失败过一次；放宽到 30 秒并在失败时打印 Edge 进程状态。日志接口限流没拿到原文，这条是按步骤耗时推断的。

## 七、证据隐私

### 22. UIA map 不是“无内容的结构数据”

- 现象：Windows 设置首页的 UIA Name/Value 直接列出登录账号、电脑/手机/蓝牙设备名和网络状态；Excel 的账户菜单、QQ 的可读树也有同类信息。
- 归因：UIA/CDP 的语义字段来自用户界面，隐私密度往往高于像素，而且纯文本更容易进入终端日志、测试输出和代码审查。
- 落点：`win.ps1 see/uia/uiaread --summary` 正常结果只打印元素数量/类型（`uiaread` 不回显过滤词，`see` 不打印窗口标题）；`tests/settings-profile.ps1` 再用 `--id` 对稳定 AutomationId 精确回读，并把截图/receipt/map 放进唯一临时目录后在 `finally` 删除；共性结论第 9 条明确把语义树按敏感证据处理。
- 证据：Windows 11 设置隔离只读档案；仓库不保存本轮原始 UIA map 或截图。

### 23. “还原后目标是前台”不等于“还原激活了目标”

- 现象：smoke 把前台 fixture 最小化再还原；还原后前台 HWND 仍是 fixture，于是断言 `restore` 抢焦点。
- 归因：`SW_SHOWMINNOACTIVE` 的保证是本次调用不激活窗口，不保证一个原本就是前台的窗口在最小化后一定失去前台句柄。旧测试只看最终值，没有比较还原前后迁移。
- 落点：`restore`/`minimize` 输出 `foreground=... before=... after=...`；仅“其它前台 → 目标”标为 `unexpected-target`、结果 partial、退出 2。`tests/window-state-contract.ps1` 无桌面覆盖五种迁移，smoke 再验证真实窗口链路。

## 八、哪些 Mac 结论在 Windows 上不成立

- **WorkBuddy 的 target 结构**：Mac 是 page + iframe，Windows 只有一个 page，`insert` 直接对它。
- **“剪映主窗能后台截、更新弹窗截不到”**：Windows 上可见的环境检测弹窗和主窗都能截；更新弹窗一直是隐藏态，无法复验。隐藏态下什么都截不到，那是状态不是能力。
- **“AX 树断在 AXWebArea”**：QQ NT 的 Chromium 树对 UIA 是开放的；WorkBuddy 才是空树。同为 Electron 两种结果，所以这条在两个平台上都不该写成通用结论。
- **`open -a <中文名>` 失败**：Windows 的对应坑不是名字，是“再启动一次不等于显示已运行窗口”。

## 九、还没变成代码的

- UIA 上限与隐私文本的取舍（第 8 条）。
- 工具不读档案：剪映的 UIA 挂死每次都要白等 6 秒 × 2，没有“这个窗口上次挂过”的记忆。
- COM 的“私有实例 + 身份核对 + Visible 时机 + RCW 释放”只活在两个测试脚本里，`win.ps1 com` 命令做的是其中最小的一段（身份核对）。
