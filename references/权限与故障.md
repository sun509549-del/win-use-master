# Windows 权限、安全闸与故障排查

**什么时候读这份**：命令返回成功但界面没动、UIA 是空树、截图黑/空/旧、窗口激活失败、坐标写被拒绝，或准备操作管理员窗口、远程桌面、锁屏与虚拟桌面。

Windows 没有一项等同 macOS TCC 的统一“辅助功能/录屏授权”。这里真正决定能力的是：**交互桌面、进程完整性级别（UIPI）、前台归属、窗口遮挡、虚拟桌面、应用自己的渲染与 UIA 实现。**

## 一、先分清三类边界

| 边界 | 典型现象 | 正确处理 |
|---|---|---|
| 可恢复环境状态 | 目标没启动、窗口还在加载、窗口句柄过期 | 重新枚举、轮询、重取引用 |
| 结构能力缺失 | UIA 无 pattern、自绘画布、无 CDP、`PrintWindow` 黑帧 | 换控制层，不重复撞同一 API |
| 安全边界 | UIPI、UAC 安全桌面、锁屏、受保护内容 | 停止并交还用户，不绕过系统策略 |

退出码约定以脚本帮助为准；本项目使用三态时，`0` 才是命令成功，`1` 是确定失败，`2` 是拒绝或未知。**退出码 2 永远不能当成功继续下一步。**

## 二、UIPI：最常见的“静默吞输入”

Windows 为进程分配完整性级别。普通 PowerShell 通常是 Medium；“以管理员身份运行”的目标通常是 High。低完整性进程向更高完整性窗口发送输入或跨进程 UI 消息，会被 User Interface Privilege Isolation 拦截。

危险之处是：`SendInput` 的返回值不能可靠说明目标应用是否接收了这次输入。表面上调用成功，目标仍可能完全没动。

工具在坐标写前应比较自身与目标进程的完整性级别：

- 目标级别高于自己：拒绝写，报告 `UIPI`；
- 级别读不到：按未知处理，不猜；
- 同级：只是通过这一道闸，不代表输入一定生效。

不要自动提权、关闭 UAC、改注册表安全策略、使用注入或安装 `UIAccess` 程序来绕过。若用户明确需要操作管理员窗口，由用户决定是否在同等权限、受控环境中重新启动整个 agent 会话；即使同级，停手线仍然有效。

## 三、UAC 安全桌面不是普通前台窗口

启用“安全桌面”时，UAC 凭据/同意界面运行在另一个 desktop。普通进程不能可靠截图、UIA 枚举或 `SendInput` 操作它。这是设计边界。

看到以下信号立即停：

- 当前输入桌面打不开或前台窗口突然无法枚举；
- 截图只剩黑屏/壁纸，且用户界面出现系统级同意提示；
- 目标是 Windows Security、凭据输入、BitLocker、智能卡、生物识别或 UAC 同意框。

绝不盲按 `Alt+Y`、`Enter`，也不请求用户把 UAC 安全桌面关闭。

## 四、坐标写的安全闸

所有会进入 `SendInput` 全局流的命令，都应按下面顺序预检。`--dry`（若当前命令支持）要走完预检但不执行输入。

| 闸 | 拦什么 | 为什么 |
|---|---|---|
| 锁屏/输入桌面闸 | 工作站锁定、没有交互桌面、UAC 安全桌面 | 输入不会落到预期会话，截图也不可信 |
| 虚拟桌面闸 | 窗口 `Cloaked` 或已知不在当前桌面 | `SendInput` 会打到当前桌面的别处 |
| 全机写锁 | 另一个 agent/进程正在借前台 | 两路键鼠和焦点会互相污染 |
| 在场闸 | 用户最近约 2 秒内有键鼠活动；等待上限后仍忙 | 不抢正在使用的电脑 |
| UIPI 闸 | 目标完整性高于当前进程，或完整性未知 | 事件可能被静默丢弃 |
| 激活/前台闸 | 激活后读回的 foreground HWND 不是目标 | `SendInput` 不携带目标 HWND |
| 遮挡闸 | 落点最上层根窗口不是目标 | 鼠标会点到遮挡窗口 |

安全闸应在**每一个动作前**重查，而不是一组操作开始时只查一次。用户可能随时切窗，窗口也可能在一步操作后弹出模态框。

`--force` 不是“成功模式”或环境拆闸。它不绕过用户在场、遮挡、完整性未知/UIPI、锁屏、UAC 或不可逆/外部动作；当前仅用于用户已明确批准某条具体终端/IDE 命令后解除 `Enter` 防误触，且不代表授权本身。

### 全机写锁

写锁保护的是整台机器的焦点与全局输入流，不只保护一个 app。锁的实现可能是命名 mutex 或临时锁文件；无论哪种，都要具备：

- 原子抢占；
- 持有者身份与时间可诊断；
- 进程异常退出后能恢复；
- 最短持有时间，只包住激活与输入，不把等待截图/模型判断包在锁里。

若锁显示忙，等待或退出；不要删未知持有者的锁文件。只有确认持有 PID 已不存在时，才按脚本提供的恢复方式清理陈旧锁。

### 用户在场

空闲秒数来自 `GetLastInputInfo`，它本身不能识别输入来自用户还是自动化。本实现把每次成功的 `SendInput` 时间戳写入短期尾迹，并且只在当前 last-input 时间戳与该记录完全相等时排除它；用户随后产生任何真实输入都会改变时间戳并重新触发等待。尾迹文件超过 10 秒不再可信。尽量把相关动作合并到一次短借焦点窗口内，仍是减少干扰的首选。

宁可误停，也不要把“用户正打字”当成性能问题去优化掉。

## 五、前台激活失败

Windows 会限制后台进程抢前台，`SetForegroundWindow` 并不保证目标最终成为 foreground。常见原因：

- 用户刚与另一个窗口交互；
- 目标最小化、正在启动或正弹模态框；
- 目标在其他虚拟桌面；
- 调用方不是当前交互会话；
- 系统前台锁定策略拒绝切换。

正确判据是调用后再次读取 `GetForegroundWindow()` 并核对 HWND/PID。失败就拒绝输入。不要用循环狂刷、模拟 `Alt`、切虚拟桌面或修改 `ForegroundLockTimeout` 注册表来强抢。

## 六、UIA 的故障分类

| 现象 | 可能原因 | 下一步 |
|---|---|---|
| 整棵树为空 | 自绘/游戏/浏览器 a11y 未开放、目标尚未就绪、权限边界 | 重取窗口并短轮询；仍空则退层 |
| 只有窗口和 Pane | WebView/Canvas 截断语义树 | 看 L0/CDP；否则 L2 |
| 控件可见但没有 Value/Invoke pattern | app 没实现该语义 | 不强行调用，换可用 pattern 或退层 |
| 元素引用突然失效 | 导航、列表虚拟化、窗口重绘 | 从窗口根重新枚举，不复用旧 ref |
| `uiaset` 成功但按钮仍禁用 | 只改 UIA value，应用内部 state 未更新 | 判 `suspected_noop`，改用 CDP insert 或前台输入 |
| `invoke` 成功但无副作用 | handler 暗拒、命中错元素、模态框截获 | 截图/读状态，不自动重复提交 |
| `uia` / `uiaread` 超过 6 秒 | provider 在枚举或属性读取中阻塞 | worker 会被终止；本轮 L1 失败，改截图/CDP |
| `uiaset` / `invoke` 超过 6 秒 | 不知道阻塞发生在动作前还是动作后 | `effect=unknown`；先独立回读，禁止自动重试 |
| 普通 app 能读，管理员 app 读不到 | UIPI/进程保护 | 报权限边界，不自动提权 |

UIA 节点的 Name、AutomationId、ControlType 可能重复或为空。优先组合多个稳定属性与父子关系定位，并把定位失败当失败；不要“取第一个差不多的按钮”。

## 七、截图故障

### `shot` / PrintWindow

| 现象 | 含义与处理 |
|---|---|
| 返回 false / 无文件 | HWND 失效、尺寸非法、目标不支持；重新枚举一次 |
| 文件存在但全黑/透明/单色 | 硬件加速、受保护内容、未渲染或空壳窗口；不能当证据 |
| 图是旧界面 | app 返回缓存表面；用状态读回或经安全闸走 `shotfg` |
| 只有边框没有内容 | 命中了壳窗口或渲染子窗口另有 HWND；重新 `windows` / `probe` |
| 最小化后尺寸异常 | Windows 使用占位坐标；不要拿它换算点击 |

判空只是启发式。纯色设计界面可能被误判为空，复杂壁纸也可能被误判为有效。最终要看预期锚点或结构状态。

### `shotfg` / 前台后重试 PrintWindow

它先试后台 `PrintWindow`；图像接近纯色时才经过安全闸借前台，并在有限重试内等待两张连续非空帧，避免把刚曝光时的过渡帧当成稳定画面。每次 `PrintWindow` 有 2.5 秒看门狗，超时不会覆盖目标图。它不是“截当前屏幕区域”，所以不能证明人眼当时看见的整层合成结果。独占全屏、DRM 视频、受保护表面、锁屏和断开的远程会话仍可能是黑图。`shotfg` 不能作为绕过安全边界的截图后门。

若命中的窗口是近空壳，`shot` 会在严格条件下检查 sibling：矩形近似相同、可见且未最小化、进程之间有父子血缘。候选渲染帧必须明显比原图丰富才替换，并在收据写 `recoveredFrom`。只按 owner 名或“看起来像同一个 app”匹配 sibling 会误截别的实例，禁止这样降级。

### HUD

HUD 用来告诉用户“agent 正在短暂操作”，应鼠标穿透、不成为前台。排除捕获依赖 Windows 版本、DWM 与捕获 API，属于 best effort：**每批证据都要抽查 HUD 是否进入截图**，不能承诺对所有录屏/截图工具隐身。

## 八、虚拟桌面与多显示器

- `DwmGetWindowAttribute(DWMWA_CLOAKED)` 能发现一部分异桌面/隐藏窗口，但 cloak 也可能来自 UWP 外壳或系统动画。
- “未 cloaked”不自动证明窗口在当前虚拟桌面且可点击；仍要激活读回与落点遮挡检查。
- 不自动发送 `Win+Ctrl+Left/Right`，不移动用户窗口跨桌面。
- 多显示器允许负坐标；不要把 `left < 0` 当非法窗口。
- 窗口跨不同缩放比例的显示器后，旧截图坐标全部作废，重新 `see`。

## 九、锁屏、远程桌面与无人值守

锁屏时 CDP/CLI 这类 L0 可能仍工作，但屏幕截图和前台输入不可用；不要因为后台业务动作成功，就伪造或沿用锁屏前的截图。

RDP 断开、会话切换、服务账户或计划任务不是普通交互桌面。常见结果是分辨率变化、窗口被最小化、DWM 表面消失、UIA 树变化、`SendInput` 发往错误 session。这个项目不承诺非交互会话自动化。需要长期任务时，把 GUI 步骤标成“需活动桌面/人在场”，结构接口可单独运行。

## 十、PowerShell 与运行环境

本项目要求 PowerShell 7（`pwsh`）。Windows PowerShell 5.1 的脚本编码、编译器和程序集解析行为不同，不在支持范围。推荐显式调用，避免 cwd 与 profile 污染：

```powershell
pwsh -NoProfile -File "$SKILL_DIR/scripts/build.ps1"
pwsh -NoProfile -File "$SKILL_DIR/scripts/probe.ps1" "目标 app"
pwsh -NoProfile -File "$SKILL_DIR/scripts/win.ps1" windows
```

若下载的脚本带 `Zone.Identifier` 而被系统拦截，先向用户说明来源与哈希，再由用户决定是否对这个仓库中的具体文件执行 `Unblock-File`。不要全局降低 ExecutionPolicy，不要关闭 Defender/SmartScreen。

Node 版本需同时提供全局 `fetch` 和 `WebSocket` 才能直接运行当前 `cdp.js`。出现 `WebSocket is not defined` 时升级 Node；不要为了省事从未知来源安装全局 websocket 包。

## 十一、快速归因顺序

1. `windows` 重新拿 HWND、PID、窗口状态；HWND 可过期也可被复用。
2. `idle` 看锁屏、前台、用户空闲、锁持有者与完整性。
3. `probe.ps1` 看是否其实有 L0/CDP，可避免借焦点。
4. L1 重新 `uia`，不复用旧 ref。
5. 只读 `shot`，检查是不是黑/空/旧/壳窗口。
6. 坐标写先 `--dry`；任何一闸未知就停。
7. 执行后用独立状态验证；不要因 no-op 立即重放追加型输入。

如果问题属于安全边界，结论应是“不能在当前权限/桌面状态下安全执行”，不是“再多试几次”。
