# 机器可读输出契约

**什么时候读这份**：脚本、agent 或 CI 需要消费 `win.ps1` 的 JSON，或需要判断 `--summary` 是否足以避免窗口标题、UIA Name/Value 进入终端日志。

## 通用约定

- `--json` 成功时 stdout 只写一个 JSON 文档；诊断错误仍写 stderr，并通过退出码 `1`（确定失败）或 `2`（拒绝/未知）表达。
- 支持 JSON/摘要的命令会拒绝未知选项和多余参数；`--summary` 拼错时不得悄悄退回 full 输出。
- 每个顶层对象都有版本化 `schema`、带时区的 `observedAt`、枚举型 `status` 和 `privacy`。消费者按完整 schema 字符串分派，不猜字段。
- 状态无法确认时使用字符串 `unknown` 和 JSON `null`；不以 `false`、`0` 或空字符串代替未知。
- 空数组表示“已知没有返回项”；`null` 表示“不存在、不适用或未知”，具体由相邻 `status` 解释。
- 默认文本输出保持兼容。JSON 用于进程间消费，不自动写文件，也不是长期取证收据。

## 当前支持命令

| 命令 | schema | `--summary` 行为 |
|---|---|---|
| `windows [filter] --json` | `win-use-master/windows-result-v1` | `windows[].title=null`，仍保留 HWND、PID、owner、class、rect 与状态 |
| `frontmost --json` | `win-use-master/frontmost-result-v1` | `window.title=null`；`none`、`unlisted`、`resolved` 明确区分 |
| `idle --json` | `win-use-master/idle-result-v1` | 隐去嵌套前台标题；计时不可用时 `status/presence/gate=unknown`、秒数为 `null` |
| `uia <target> --json` | `win-use-master/uia-elements-result-v1` | `items=[]`，只保留总数、首轮数和 ControlType 计数 |
| `uiaread <target> ... --json` | `win-use-master/uia-read-result-v1` | `items=[]`，保留计数、类型、查询形状与安全分页信息 |
| `doctor --json` | `win-use-master/doctor-report-v1` | doctor 自身已是脱敏诊断；`--json` 与 `--summary` 互斥 |
| `probe.ps1 <app> --json` | `win-use-master/probe-report-v1` | 隐去查询值、目标名/路径、进程明细、原始能力证据、窗口明细和警告正文，只保留状态、计数与 L0–L3 路由 |
| `cache show --json` | `win-use-master/capability-cache-view-v1` | `entries=[]`，只保留 fresh/expired/invalid 数量和非授权声明 |
| `cache record/clear ... --json` | `win-use-master/capability-cache-operation-v1` | `key=null`，不回显输入报告路径；保留动作、状态和剩余数量 |
| `cleanup --json` | `win-use-master/cleanup-plan-v1` | `items=[]`，只保留候选/eligible/refused 数量、策略和零副作用声明 |
| `benchmark --json` | `win-use-master/performance-report-v1` | 只输出聚合统计；不保存原始样本、路径、标题、正文、selector、PID 或端口 |
| `restore/minimize <target> --json` | `win-use-master/window-state-result-v1` | `before/after.title=null`；保留请求状态、回读状态、前台迁移和 effect |
| `cdp.js <port> list --json` | `win-use-master/cdp-targets-result-v1` | `targets=[]`，保留总数、page 数与 target 类型计数 |
| `cdp.js <port> inspect <target> <selector> --json` | `win-use-master/cdp-inspect-result-v1` | 隐去 target title/URL；控件只含角色、可见/禁用/可编辑、正文长度与占位符状态 |

CDP 的本批结构化范围只包括 `list` 和 `inspect`；`snapshot/find/wait` 仍是人读输出。写命令继续以 `action-receipt-v1` 为权威结果，不为了统一终端 JSON 再复制一份正文或动作证据。

## 隐私语义

`privacy.mode` 为 `full` 或 `summary`，`redactedFields` 列出被隐去的路径。UIA 的 `privacy.collection=unchanged` 表示摘要只限制 stdout 呈现，worker 仍为计数、类型和筛选读取必要元数据；它不是“不采集正文”的保证。敏感页面仍应先缩小到精确 AutomationId，再加 `--summary`。

窗口查询词、旧 UIA 过滤词以及结构化 UIA 的 ID/Name 值不会复制进 JSON。报告只记录是否使用过滤、查询模式和各条件是否存在。`uiaread` 分页的 continuation 会保留，因为它是读取下一页所需的不透明游标；不要把它当鉴权凭证或抄入公开台账。

`probe` 的查询值在 full/summary JSON 中都不回显；full 会给出解析后的 app 身份、路径和能力证据，summary 则将这些可能暴露用户名、安装位置或应用身份的字段置空/置为空数组。摘要不减少只读采集范围，因此 `privacy.collection=unchanged`。

`probe.cache` 是建议性状态：`fresh` 才可能提供 `advisoryOrder`，`expired/version-changed/no-match/disabled/invalid` 均不使用缓存。`trustedForAuthorization` 固定为 false。`cache show` 的 full entry 也只含能力缓存白名单；窗口标题、UIA/DOM 正文、账号、命令行、路径、PID/端口从未落盘，而不只是 summary 时隐藏。完整边界见 [`能力缓存.md`](能力缓存.md)。

`cleanup` 当前只输出 dry-run 计划，`applyAvailable=false`；full 仅列候选目录叶名、判定、原因、manifest 时间、owner 状态与元数据大小，不输出绝对路径、不读取 payload 内容、不复制 manifest 未知字段。summary 清空 `items` 但保留计数。报告的 files/directories deleted、files written 和 processes stopped 固定为 0，详见 [`临时数据治理.md`](临时数据治理.md)。

`benchmark` 的 full 与 summary 都是 aggregate-only；区别只记录呈现模式，不扩大采集。`windows` 子测固定使用 summary，UIA 只接合成 provider，CDP 只接本次自启的临时无头 Edge。报告记录版本、min/p50/p95/max/mean、预算超限数，以及浏览器/owner 进程/临时目录的创建回收计数，不嵌入子命令输出或原始样本。详见 [`性能基线.md`](性能基线.md)。

CDP `list` 的 full JSON 也不会输出 `webSocketDebuggerUrl`，并始终删除 URL query/fragment；summary 进一步清空 target 列表。`inspect` 从采集层就不读取正文，只返回 `textLength` 和布尔状态；报告保留解析后的 target id，但不新增原始 target 查询字段或 CSS selector 字段。summary 下的自动 target 选择及歧义/未命中、CSS 未命中/语法错误同样不打印 title、URL 或原始查询值。

`full` 模式会输出窗口标题或 UIA Name/AutomationId/Value，可能包含文档名、联系人或正文。进入日志、Issue、CI artifact 或公开仓库前应改用 `--summary`，或按取证规范生成受控、脱敏的发布件。密码控件的 Value 在采集层即不读取；即使 `full` 模式也不恢复。

## 主要字段

- 窗口记录：`hwnd`、`pid`、`owner`、`title`、`className`、`state`、`rect`、`flags`。
- `frontmost.status`：`resolved` 表示成功关联窗口记录；`unlisted` 表示系统给出非零 HWND 但本轮枚举未关联；`none` 表示系统没有前台 HWND。
- `idle.presence`：`present`、`idle` 或 `unknown`；`coordinateGate.status` 对应 `wait`、`eligible` 或 `unknown`。它只描述闸前状态，不授予任何写操作。
- UIA `typeCounts`：稳定数组 `{ controlType, count }`，按类型名排序。摘要模式的 `items` 是空数组，不代表 UIA 树为空；看顶层 `status` 与 `counts.returned`。
- `uiaread.query`：仅包含 `mode`、条件存在性、limit 与 continuation 是否使用，不包含原始查询值。
- `uiaread.page`：仅结构化分页时存在；无分页契约的兼容读取为 `null`。
- `probe.capabilities`：`l0` 表示首选结构接口或候选，`l1/l2/l3` 使用 `available/partial/eligible/blocked-*/unknown/unavailable` 等保守枚举；缓存不能据此授权动作。
- `probe.cache`：`status`、`used`、`trustedForAuthorization=false`、时间和 `advisoryOrder`；它只能调整后续只读探测顺序。
- `capability-cache-view.counts`：`total/fresh/expired/invalid`；summary 的 `entries=[]` 不表示 cache 为空，应读取计数。两个 cache schema 的 `authorization.participates/trusted` 均为 false。
- `cleanup-plan.items[].decision`：`eligible/refused` 只表示只读判据；eligible 不是删除授权。`reasons` 解释 manifest、到期、owner、reparse point 或枚举边界，summary 时应读取 `counts`。
- `performance-report.results`：`windows` 区分 first/repeated fresh process；`uia.cases` 固定报告 100/300/1000 元素；`cdp.status` 可为 completed/skipped/disabled/failed。缺可选 Node/Edge 时顶层可为 partial，不能把缺样本解释成 0 ms。
- `window-state.status`：`planned` 表示 `--dry` 未执行，`completed` 表示状态回读符合请求，`partial` 表示状态已改变但目标意外取得前台，`error` 表示调用或回读失败，`refused` 表示隐藏/cloaked 等前置拒绝。相应 `effect` 为 `not-applied/unchanged/changed/partial/unknown/none`。
- `window-state.focus.transition`：沿用 `unchanged/target-already/released-by-windows/changed-external/unexpected-target`；未观察时是 `not-observed`，前台 HWND 未知/不存在时为 `null`。
- `cdp-targets.typeCounts`：摘要清空 `targets` 后仍可判断 page/background 等 target 构成；空数组表示已知没有目标。
- `cdp-inspect.element`：仅为安全元数据，不含 text/value/HTML；`targetSelectorIncluded` 与 `elementSelectorIncluded` 固定为 false。

schema 升级若删除字段、改变类型或重解释枚举值，必须发布新的 `*-vN`；新增可选字段仍需同步契约测试和本文。调用方遇到未知 schema 应退出或降级为人工检查，不能按旧结构继续动作。
