# Windows 四层控制面详解

**什么时候读这份**：`probe.ps1` 探完仍不知道走哪一层、UIA 看得到却写不动、CDP 端口连不上、坐标点击被安全闸拒绝，或截图成功但内容发黑、空白、陈旧。

这套工具的顺序不是“先看图再点”，而是：**先找结构接口，再找语义控件；只有前两层都不通，才借前台走坐标；像素贯穿全程做验证。**

## 总览：读写分开选层

| 层 | Windows 控制面 | 读 | 写 | 主要限制 |
|---|---|---|---|---|
| L0 | app CLI、COM 对象模型、URL protocol、本地端口、CDP | 通常后台 | 通常后台 | 接口是否存在、是否需要认证、是否允许安全地启动 |
| L1 | Microsoft UI Automation（UIA） | 通常后台 | 可后台调用 pattern | 自绘、虚拟化、Chromium a11y、高完整性进程会断树或暗拒 |
| L2 | 前台窗口 + `SendInput` + 窗口内坐标 | 不用于读 | **必须借前台** | 遮挡、用户输入、UIPI、锁屏、虚拟桌面、DPI |
| L3 | `PrintWindow` 窗口像素；`screen` 桌面合成 | 尝试后台 | 像素本身不写 | 最小化、硬件加速、受保护内容可返回黑帧或旧帧；合成图含遮挡物 |

两条边界必须先记住：

1. Windows 没有 macOS `CGEventPostToPid` 的可靠等价物。`PostMessage(WM_*)` 只是向消息队列塞消息，不等于真实输入；Chromium、DirectUI、自绘和游戏常完全不认。这个项目的坐标输入走 `SendInput`，因此作用对象永远是**当前交互桌面的前台窗口**。
2. API 返回成功只是“调用被接收”。UIA `SetValue`、`Invoke`、`SendInput`、`PrintWindow` 都可能在应用层没有产生想要的结果。每一步都要读回、截图或检查最终副作用。

## L0：结构接口是默认起点

### 1. app 自己的 CLI

先看安装目录、帮助参数、官方文档和正在运行进程的命令行。CLI 通常最稳定，也最适合无人值守，但不要把猜出来的私有参数当正式接口。会发布、删除、覆盖或提交的 CLI 命令仍受停手线约束。

`probe.ps1` 是只读探针：它不会为了“试试看”而启动、关闭或带参数重启目标 app。未运行时，动态端口、窗口、UIA 和命令行信号为空是正常结果。

### 1b. COM 对象模型

Office、WPS、Photoshop、AutoCAD、Visio 等在 Windows 上的结构接口经常是 COM，而不是 CLI。`probe.ps1` 只读枚举指向该 exe/安装目录的 `LocalServer32` 与 TypeLib，不实例化；`win.ps1 com <ProgID> --dry` 分开显示 64 位与 32 位注册表视图各指向哪个 exe，去掉 `--dry` 会 CoCreate 一个私有实例、按 `Hwnd → pid → exe` 报出真正应答的程序再 Quit 它（不碰任何预存在的进程，也不读写文档）。注册了 ProgID 只说明对象模型存在：

- `New-Object -ComObject <ProgID>` 启动的是私有自动化进程（Excel `/automation -Embedding`、WPS `/prometheus /et /Automation` 均实测如此），不是连接用户已打开的文档；只对这个新 pid 写、存、Quit。
- 身份要核对，不能信名字：WPS 在 32 位注册表视图把 `Excel.Application.12` 指向自己的 `et.exe`，窗口类名也叫 `XLMAIN`，`Application.Name` 报 “Microsoft Excel”。用 `Application.Hwnd → pid → exe 路径` 判断到底谁在应答；要 WPS 就用 `KET.Application`。
- 写值前先让窗口存在：Excel 的 `Visible=True` 在没有工作簿窗口时被忽略，`Workbooks.Add()` 之后 `Hwnd` 还会换成新窗口。
- PowerShell 细节：COM 对象不能从函数 `return`（集合会展开，`-NoEnumerate` 又让属性写入失败）；`Range.Value2` 在 pwsh 7 下写 `[double]` 不写 Int32；所有 RCW 显式 `FinalReleaseComObject` 后再 Quit，否则进程挂到 DCOM ping 超时。
- 最强验证不在宿主里：另存的 xlsx 用 zip 解开读 `sheet1.xml` 的 `<f>`/`<v>`，或用第二个私有实例重新打开读回。
- 先查官方对象模型文档，只读属性验证；写与保存/发送同样受停手线约束；
- 不要把 ProgID 抄进通用正文，版本和 bitness（x86/x64）都会变。

### 2. URL protocol

Windows 的协议注册可能来自注册表、快捷方式或 AppX 清单。发现 `example://` 只说明系统知道由谁接，不说明路由格式、安全性或幂等性。打开协议可能启动 app、切换页面，甚至触发业务动作；先在档案中记录来源，未知路由不盲猜。

协议只适合表达“打开某资源”时优先试。填表、提交、上传和复杂状态变更不要硬凿成 URL。

### 3. 本地端口与 CDP

Electron、CEF、WebView2 或带内嵌 Chromium 的 app 可能暴露 Chrome DevTools Protocol：

```powershell
& "$SKILL_DIR/scripts/probe.ps1" "目标 app"
node "$SKILL_DIR/scripts/cdp.js" 9333 list
node "$SKILL_DIR/scripts/cdp.js" 9333 snapshot auto
```

只有本机 `http://127.0.0.1:<port>/json/version` 或 `/json/list` 返回了符合 CDP 的信息，并且监听 socket 的 owner PID 能追溯到目标 exe/进程树，才算找到目标 app 的 CDP。监听端口不等于 CDP：它也可能是带认证的 JSON-RPC、更新服务、业务 IPC，甚至另一个 app 的 CDP。端口会漂移，不能把某次实测端口抄进通用正文。

如果目标 app 只有在 `--remote-debugging-port=<port>` 下才开放 CDP，通常意味着要重启。**重启会丢未保存状态，必须先向用户说明并取得同意。** 不要给用户的日常浏览器开启无保护的远程调试端口；本工具的 CDP 面向用户明确授权的桌面 app 实例。

`open --cdp` 在端口归属通过后签发 30 分钟 `cdp-session-v1`，绑定监听 owner 的 PID、exe 路径、进程启动时间以及当时的 page target id。后续每个修改命令都由 `cdp.js` 自行复核，不能靠调用方口头承诺；授权集合含多个 page target 时写操作禁止 `auto`，必须从 `list` 使用准确 target id。`--dry` 只做检查，不生成会话。会话过期、端口/PID 被复用、新 target 未在授权集合时退出 2，重新 `open --cdp` 后才能写入。默认文件位于 `%LOCALAPPDATA%\win-use-master\sessions`，测试通过 `WIN_USE_MASTER_CDP_SESSION` 使用临时隔离文件。

`cdp.js` 的强弱顺序：

- 读：`list` → `snapshot` / `find` → `inspect`（脱敏状态、字符数、占位符）→ 必要时 `html` / `eval-read`。`eval` 是只读兼容别名，浏览器无法证明无副作用时拒绝；任意脚本写入必须单独使用 `eval-unsafe --allow-side-effects` 并审查动作回执，不能放进 `act`。
- 写文本：优先 `insert`（CDP `Input.insertText`），它比直接改 `el.value` 更容易触发框架状态。
- 撤回：`press SelectAll`（Ctrl+A，只选中当前编辑宿主的内容）再 `press Backspace`，两者都是真实键事件，Slate/ProseMirror 的 state 会随之回退；`text` 直接改 `textContent` 做不到。WorkBuddy 实测：insert 后发送键 `disabled true→false`，撤回后 `false→true`，占位符重现。
- 点击：普通 DOM 可用 `click`；组件只认真实指针事件时用 `mouse`。
- 等待：用 `wait` 轮询状态，不用固定睡眠假定成功。
- 多步：用 `act`；任一步未知或找不到元素就停，不在后续步骤继续猜。

所有 CDP 修改命令（`click/text/mouse/insert/press/eval-unsafe/act`）都会形成 `action-receipt-v1`。长期证据在命令末尾显式给 `--receipt <path>`；否则只写系统临时目录。收据不复制页面正文、输入正文、原始 CSS 或原始 eval 表达式：selector 是短 ref，或仅保留 SHA-256 与长度；`eval-unsafe` 表达式同样只保留 SHA-256 与长度；before/after 是可见交互树的摘要哈希与元素数。任意脚本还可能改变网络、存储或服务端状态，因此即使观察到 DOM 差分，`eval-unsafe` 的总 effect 也始终标为 `unknown`。其它 DOM 差分只能把结果标成 `partial` 或 `suspected_noop`，业务副作用仍需独立回读。异常发生时写 `effect=unknown`，不要自动重放非幂等步骤。

HTTP target 枚举和 WebSocket 握手各有 5 秒截止时间，单次 CDP 请求是 6 秒；`auto` 最多为前 12 个候选各花 1.5 秒评分，`act` 最多 200 步/120 秒。超时属于结果未知而非确定失败：修改命令照样写收据并退出 2。请求超时会关闭本轮 WebSocket，防止迟到响应被后续步骤误用。

输入控件、文本域和 contenteditable（含 `role=textbox`/`searchbox` 的 Slate、ProseMirror 编辑器）的终端差分只显示字符数，避免旧值/新值经日志旁路泄露；判据是采集时打的 `editable` 标记，不是元素 kind 的后缀。动作失败后让 Node 自然排空 CDP WebSocket；不要在 close 尚未完成时强制 `process.exit`，Windows/libuv 可能把普通退出码 1 变成进程断言崩溃。

CDP 能后台工作，也不代表能跨进程完成系统文件选择框、UAC、原生菜单、下载后的系统确认框。出现这些边界就交还用户或换到明确允许的系统层路径。

## L1：UI Automation 是语义层，不是万能后台控制

UIA 暴露的是 `AutomationElement` 与控件 pattern。常见可用能力包括：

- `ValuePattern`：读写文本框值；注意 RichEdit/WinUI 编辑器（记事本 11 的 `RichEditD2DPT`）把文本区暴露为 Document 而不是 Edit，同样带 ValuePattern，`uia` 会列出它，`first` 在没有 Edit 时兜底选它；
- `InvokePattern`：执行按钮默认动作；
- `TogglePattern`、`SelectionItemPattern`、`ExpandCollapsePattern`：操作有对应语义的控件；
- `TextPattern`：读取文档型文本，通常不能直接替代真实键盘输入；
- `ScrollPattern`：滚动语义容器。

工作顺序：

```powershell
& "$SKILL_DIR/scripts/win.ps1" uia <hwnd>
& "$SKILL_DIR/scripts/win.ps1" uiaread <hwnd> [模糊过滤词]
& "$SKILL_DIR/scripts/win.ps1" uiaread <hwnd> --id <AutomationId> [--summary]
& "$SKILL_DIR/scripts/win.ps1" uia <hwnd> --summary
& "$SKILL_DIR/scripts/win.ps1" uiaread <hwnd> --summary
& "$SKILL_DIR/scripts/win.ps1" uiaset <hwnd> <ref> "文本"
& "$SKILL_DIR/scripts/win.ps1" invoke <hwnd> <ref>
```

以脚本实际 `--help` 为准；`ref` 是当次枚举得到的短期引用，不跨窗口重绘、导航或进程重启复用。

### 哪些结果不能算“通了”

- UIA 枚举返回 0：可能是真没语义树，也可能是树延迟、虚拟化、目标高完整性、WebView 尚未启用可访问性或当前节点选错。
- `uiaset` 没报错：可能只改了外观，没有触发 React/Slate/自绘控件内部状态。
- `invoke` 返回成功：目标 handler 可能忽略了调用，或动作产生在另一个窗口。
- 能读到 Name：不等于能写；能写 Value：不等于依赖按钮已经启用。

`uia` 面向可操作元素和短 ref；`uiaread` 面向 Text/Document/Edit/Status/Header，不读取密码字段的 Value/Text。敏感窗口先对两者加 `--summary`，终端只显示数量与 ControlType 统计；确认需要后用 `uiaread <hwnd> --id <AutomationId>` 精确读。两者分开可以避免静态文本改变 action ref 的编号，同时给“动作后读回”一条稳定入口。

`--id` 是区分大小写的 UIA PropertyCondition，和可读类型条件一起交给 provider；先检查候选唯一，再读 Name/Value，最后应用输出限制。所以目标在整树第 300 项之后仍可命中；零/多匹配、失效、无可读内容都退出 2，不能靠调小 Limit 隐藏歧义。旧的位置过滤词仍在读取最多 300 项后做 Name/Value/AutomationId 子串匹配，不保证唯一，也不隔离无关正文；不能和 `--id` 混用。`--summary` 只限制终端输出、不限制采集，且不回显过滤词或 ID；它不为磁盘证据或所有错误诊断提供通用脱敏。

`invoke` 还多一道动作前语义闸：主进程先让只读 worker 把 ref 重定位到当前 Name/AutomationId/ClassName，按 `config/risk-actions.json` 检查发送、提交、付款、删除、覆盖保存等最终动作；无标签 Button/Hyperlink/MenuItem 也按未知风险拒绝。只有预检通过才生成 before 图并进入 action worker，action worker 在调用 pattern 前再次按同一份规则复核。规则文本来自单一版本化 JSON，避免 UIA 与 CDP 各自维护一份逐渐漂移的关键词。

Windows UIA provider 可以在 `FindAll`、属性读取或 pattern 调用中无限阻塞。主命令不在 agent 进程内直接调用它们，而是把 HWND、窗口边界和请求 JSON 通过 stdin 交给独立 `uia-worker.ps1`，6 秒后仍未完成就终止该进程。枚举/读取超时只是本轮 L1 不可用；`SetValue`/`Invoke` 超时则必须视为动作可能已经发生，保存可得的 after 收据并返回 `effect=unknown`，不能重放。ValuePattern 正文不放到 worker 命令行。

所以 UIA 写入至少要再看一项独立信号：读回值、按钮 `IsEnabled` 变化、像素变化、列表新增项或文件落盘。对 contenteditable、自绘输入区和虚拟化列表尤其如此。

UIA 通常不需要独立的“辅助功能授权”，但不等于没有安全边界。普通完整性进程面对管理员窗口、受保护进程或安全桌面时可能读不全、调用失败或静默无效。不要通过关闭 UAC、修改系统安全策略或注入进程来绕过。

## L2：前台 `SendInput` 是降级路径

当 L0、L1 都不满足任务，才使用窗口坐标。推荐入口是 `op`；单独的 `clickin`、`hoverin`、`scrollin`、`type`、`key` 用于可拆解且容易验证的动作。

### 为什么必须借前台

`SendInput` 注入全局输入流，不携带目标 PID 或 HWND。工具能做的是：

1. 确认目标窗口存在且不是已知的异桌面/不可交互状态；
2. 取得全机写锁；
3. 等用户空闲；
4. 检查完整性级别；
5. 激活目标并再次确认它确实成为前台；
6. 确认落点最上层仍属于目标；
7. 才移动鼠标、点击或打字；
8. 截图与状态验证后尽快还原前台和指针（若实现与当前状态允许）。

其中任何一步未知都应拒绝，不应“碰碰运气”。`SetForegroundWindow` 返回值也不是最终凭证；Windows 有前台切换限制，必须读回 `GetForegroundWindow()`。

键盘本身没有控件语义，尤其 Enter 既可能换行，也可能提交表单、发送聊天或执行终端命令。当前实现选择 fail-closed：Enter、Ctrl+S、Ctrl+Shift+S、Alt+F4 在借焦点、截图或 SendInput 前拒绝，`--force` 不解除。需要最终提交、保存或关闭时由用户亲自完成。

### 坐标

坐标以窗口客户/窗口矩形和当前截图为上下文，不存全局屏幕绝对坐标。窗口会移动，混合 DPI、多显示器负坐标、标题栏和阴影都会改变换算。

推荐存三件东西：

```text
归一化坐标 (nx, ny) + 可见锚点描述 + 实测窗口尺寸/DPI/版本
```

归一化换算：

```text
窗口内 x = nx × 当前窗口宽
窗口内 y = ny × 当前窗口高
屏幕 x = 当前窗口 left + 窗口内 x
屏幕 y = 当前窗口 top  + 窗口内 y
```

即使工具支持 `@截图` 自动换算，也必须保证那张图来自同一个窗口状态。旧截图、缩放后的加工图、裁掉标题栏的图片都不能直接当坐标基准。

`eN@map.uia.json` 形式的点位带有 UIA 语义，因此 click/op 在进入坐标闸前也能复用最终动作规则。纯像素与归一化坐标没有可信标签，无法靠 denylist 判断一个点是不是“发送”按钮；这一盲区必须由停手线和用户最终确认兜底，不能把规则没有命中解释为许可。

混合 DPI 是 Windows 特有高风险点：窗口跨显示器后 DPI 感知模式可能变化，逻辑像素与物理像素不再一一对应。症状是整个界面按固定比例点偏。此时重新 `see`，不要手工补一个永久偏移量。

### 遮挡与虚拟桌面

落点被别的窗口盖住时，`SendInput` 会点到遮挡者。遮挡闸要用屏幕点命中的顶层根窗口复核目标，而不是只看目标是否“前台”。

DWM 的 `Cloaked` 是目标在其他虚拟桌面、UWP 外壳隐藏或系统过渡状态的强信号，但不是一份完整的虚拟桌面 API。工具应对已知 cloaked 状态拒绝坐标写；无法确定当前桌面时也不自行发送 `Win+Ctrl+方向键` 切桌面。请用户把目标窗口移到当前桌面。

## L3：像素是验证层，`PrintWindow` 不是屏幕真相

`shot` 通过 `PrintWindow(..., PW_RENDERFULLCONTENT)` 请求目标窗口自行绘制。它的价值是：窗口即使被遮挡，仍**有机会**得到干净的窗口图。但“有机会”是边界，不是承诺：

- 最小化窗口可能没有可用表面，或窗口矩形是 `-32000` 一类占位值；
- 未显示的窗口（`windows --all` 里 `state=hidden`：托盘态、尚未显示的编辑器、后台弹窗）整帧都是空的，这是窗口状态不是渲染拒绝；`shot` 会直说，`screen`、`shotfg` 与坐标写都拒绝，因为显示它属于替用户改状态；最小化窗口在用户要求操作该 app 时可用 `restore`（`SW_SHOWNOACTIVATE`，不改前台）放回原位，看完 `minimize` 还原；
- 刚还原的窗口第一帧可能直接失败（QQ 实测），`shot` 会等 400 ms 重试一次，不再多；
- Chromium、WebView2、DirectComposition、视频、游戏和硬件加速画布可能返回黑图、透明图或旧帧；
- DRM、受保护内容和安全桌面本来就不应被捕获；
- `PrintWindow` 返回 true 只代表调用完成，不代表图像有效。

因此 `shot` 要同时报告尺寸、窗口状态与粗略判空；模型仍需检查图片内容。每次 `PrintWindow` 有 2.5 秒看门狗，超时任务只能清理自己的临时文件，不能晚到后覆盖目标图。若当前 HWND 是接近纯色的壳，工具只在窗口几何近似相同且进程有父子血缘时尝试 sibling；候选明显更丰富才采用，并把两者身份写进收据。

判空本身也是启发式，而且有一类假阳性无法用像素消除：判空统计的是裁掉标题栏/工具栏/边框后的内容区，空白的记事本文档和一个只画了标题栏的黑壳窗口在这里都是 1 个颜色桶，整帧又都有约 20 桶（标题栏本身就贡献这么多）。2026-09-08 实测后工具的处理是：内容区单色时收据额外写 `frameColorBuckets`；整帧也接近纯色才说“可能拒绝后台渲染”，否则说“内容区单色但边框已渲染，可能是空文档/画布，也可能是壳窗口”；`see` 拿当次 UIA 表做语义交叉——读到空的 Document/Edit 就写明“与空文档一致，不是截图失败”，读到非空文本控件却像素单色才提示内容层可能未渲染；`shotfg` 在 UIA 能读到空文档且没有非空文本控件时不再借前台，因为借前台不会给空文档添内容。

`shotfg` 是明确的降级：后台图疑似空时，经过完整安全闸后短暂借前台，在有限重试内要求两张连续非空帧再归还。它只是在帮助“后台不渲染、前台才刷新”的 app，**不是屏幕区域抓取，也不能保证最终有内容**。若目标进程树已有 CDP，空图提示应给出准确端口，优先转向页面截图。

`see` 面向决策，不是原始物证：它可以组合窗口收据、缩略图和 UIA 表，便于选层与定位。账号、聊天、设备等敏感页用 `--summary`，只在终端打印元素数量、类型和 map 路径；本地截图与 map 没有因此脱敏，仍须受控保存、按需读取并及时清理。真正归档时保留 `shot`/`screen`/CDP 原图与命令收据。

### `screen`：桌面合成交叉验证

`PrintWindow` 请目标自己画；`screen` 用 `CopyFromScreen`/`BitBlt` 抓当前桌面合成结果。两者回答不同问题：

```powershell
& "$SKILL_DIR/scripts/win.ps1" screen .\evidence\raw\desktop.png
& "$SKILL_DIR/scripts/win.ps1" screen .\evidence\raw\window-on-desktop.png --window <hwnd>
& "$SKILL_DIR/scripts/win.ps1" screen .\evidence\raw\region.png --region 100 100 800 600
```

- 不激活、不移动鼠标。锁屏/最小化/cloaked 窗口拒绝 `--window`。
- `--window` 与 `--region` 不能同时用。`--region` 是虚拟屏幕物理像素，允许负坐标；超出屏幕的部分会被裁剪，裁剪后的图不能当 `@` 坐标参考。
- 图中包含通知、其它窗口、可捕获的 HUD。`--window` 会在中心和四象限采样 `WindowAtPoint`，报告有多少点被遮挡。
- 用途：判断 `PrintWindow` 是否交出陈旧/黑帧。不能证明“用户没被打扰”，也不能替代 CDP 页面截图。
- `open --background` 请求 `STARTF_USESHOWWINDOW + SW_SHOWNOACTIVATE`。这是建议，不是契约：Electron/Qt/Store 启动器常忽略。工具会回读 `GetForegroundWindow`；若目标抢了前台，在用户空闲时尝试把原窗口还回去（用户正在打字时不发 Alt 解锁）。档案应记录该 app 是否遵守不激活请求。

### 横向滚动

`scrollin ... --horizontal`（或 `--dx`）发送 `MOUSEEVENTF_HWHEEL`，正 delta 向右。步数限制仍是 200。画布和宽表格只认真实滚轮流，不要用点滚动条代替。

## 验证阶梯

从弱到强：

1. 工具返回且退出码为 0；
2. 同一控件读回值或 UIA 属性变化；
3. 截图看见预期内容；
4. 依赖状态变化，例如按钮由禁用变可用；
5. 业务副作用出现，例如列表新增、文件以预期哈希落盘。

像素差分只能回答“某块区域变了没有”，不能回答“变得对不对”。光标闪烁、悬停高亮、动画和时钟都会制造变化；`effect=confirmed` 仍需语义确认。`effect=suspected_noop` 也不是自动重试许可，应先重新观察，避免把追加型输入执行两遍。

## 等 UI 就绪

- L0/CDP：轮询 DOM、文本或网络可见状态，设超时。
- L1/UIA：重新从窗口根节点枚举，不缓存跨导航引用；等待目标属性稳定。
- L2/L3：连续截图时排除光标、视频和动画区域，或只比较落点附近。
- 模态框：先读文字，再决定是否继续；不要按默认按钮试错。

固定 `Start-Sleep 2` 只能用作很短的渲染缓冲，不能作为“应用已完成”的证据。
